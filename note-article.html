耳しかない素人が、AI と一年で 12 個の VST プラグインを作って、 ついには自作の公式サイトまで持ってしまった話。 素人サラリーマンの執念の音響開発記録 ／ 公式サイト編

こんにちは、OTODESK です。
昼間は普通のサラリーマンをやっていて、家に帰れば子の良きパパ、ただ音楽が好きな一個人です。音響工学を専門で学んだことは一度もありません。ただ、若いころから DAW を触り続けて、自分の頭の中で鳴っている音と、市販プラグインで作れる音とのあいだに、ずっと埋まらない距離を感じていました。

その距離を埋めるために、無謀にも自分で VST プラグインを開発し始めて、気がついたら一年で 12 個もリリースしていました。そして先日、ついに OTODESK の公式サイトまで作ってしまいました。

otodesk4193.github.io
OTODESK_Official_Site | VST Plugins

物足りないなら、自分で作る。— C++ と JUCE でハンドビルドした、オープンソースの VST3 プラグイン群。

この記事では、その公式サイトを「素人がどうやって、たった数日で形にしたか」という制作日記をお届けします。同じように「自分の音」を追いかけている VST 開発者の方、これから何か始めたい音楽制作者の方の、何かの背中押しになれば嬉しいです。

第一章：なぜ「自分のサイト」が必要だったのか

そもそも、僕がプラグインを作り始めたのは、商用プラグインへの不満からでした。Schroeder、Moorer、Jot ── 商用リバーブが拠って立つ DSP の土台は、1960年代から今までほとんど更新されていません。違いはプリセットと UI と価格だけ。それなのに、新作リバーブが出るたびに「次世代」「革新的」と煽られて、3万円、5万円と財布から飛んでいく。

「だったら、自分で作ればいい」

このたった一行の決意が、すべての始まりでした。最初は C++ も JUCE もろくに分からない状態で、AI（Gemini と Claude）を壁打ち相手に、JUCE のドキュメントと DSP の論文と、プロエンジニアの技術ブログを行き来して、難解な専門用語を一つずつ自分の言葉に翻訳しながら、設計と実装を進めてきました。

ビルドエラーは、もはや数えていません。本当に。
正直、何度心が折れかけたか分かりません。それでも諦めなかったのは、頭の中で鳴っている音を、誰かが作ってくれるのを待っていられなかったからです。執念だけは、誰にも負けない自信があります。

そうして気がつくと、GitHub のリポジトリには 12 個のプラグインが並んでいました。BassSynth、NEOTO Pre、LUMINA、Next-Gen Kick、Otodesk Sampler、GlitchNexus、Rhythm Matrix、MULTI-OTO、CHIMERA Filter、ChordMatrix、BassLineMatrix、そして最新作の Ambience。

でも、ふと思ったんです。

これだけ作ったのに、誰にも知られていない。
GitHub のリポジトリページは、開発者には便利でも、音楽制作者には敷居が高い。
「使ってもらう」ためには、もっと普通の「サイト」が必要なんじゃないか？

第二章：素人が「Ableton 公式サイトみたいなやつ」を作りたいと言った日

サイト制作の経験は、ゼロ。HTML タグの書き方も覚えていません。
それでも、僕には憧れがありました。Ableton の公式サイトです。あの、白い余白と、シャープなタイポグラフィと、装飾のための装飾をしないあの潔さ。あれが好きで、あれを目指したい。

そこで、Claude に正直に伝えました。

私の開発した VST3 を紹介するサイトが欲しい。
Ableton のホームページにあるような洗練された感じで。

すると Claude は、いきなりコードを書き始めるのではなく、こちらの意図を確認する質問を山ほど投げてきました。配色は？ ヒーローの構成は？ プラグイン詳細はどう見せたい？ Tweaks 機能は要る？ ── 正直、最初は「もう作っちゃってよ」と思ったんですが、後から振り返ると、この最初のすり合わせが、サイトの方向性を決定づけていました。

僕が選んだのは、こんな方向性です：

  • ミニマル・モノクロ（白背景に、シャープなタイポグラフィ）
  • アクセントカラーはシアン（後に各プラグインごとに色を変えた）
  • スクロール連動アニメーションあり
  • 日英切替対応
  • 2-3 案を比較してから決める

そして、サイトのキャッチコピーは、自分が一番大切にしている言葉を選びました。

物足りないなら、自分で作る。

Claude はこの言葉のリズムをそのまま活かして、「物足りない」と「自分で作る」をそれぞれ別の色で強調するレイアウトを提案してくれました。コーラルレッドとスカイブルー。読んだ瞬間、頭の中で「これだ」と鳴りました。

第三章：プラグインを並べる、ということ

サイトの肝は、12 個のプラグインをどう見せるか、です。
ここで僕がこだわったのは、「Apple のプロダクトページ」と「LP の裏ジャケット」のあいだのような佇まいでした。

Claude は、まずプラグイン一覧を「インデックスリスト」として並べることを提案してきました。番号・名前・カテゴリ・タイプ・年。ホバーすると他の行が薄くなり、選択した行が強調される。これがめちゃくちゃ気持ちよかった。手元のマウスに、プラグインたちが反応する。それだけのことが、こんなに楽しいとは。

その下に、各プラグインの詳細カードが続きます。プラグイン UI の SVG モックアップ（実物のスクリーンショットを使わず、敢えてキャラクタライズした抽象画にした）、タグライン、説明文、機能箇条書き、ダウンロードボタンとソースコードリンク。

説明文を書くときに、僕は GitHub の各プラグインの README をそのまま Claude に貼り付けました。「これを参考に、サイト用にプロのライティングで書き直してくれ」と。返ってきた文章は、技術用語を残しつつも、音楽制作者の言葉に翻訳されていて、自分でも「あ、これは確かに自分のプラグインだ」と思える、不思議な解像度の高さがありました。

CLAUDE と組む上での発見
AI は「すべてを任せる相手」ではなく、「自分の頭にあるイメージを言語化してくれる、超優秀な後輩」だった。指示を放り投げると並のものしか返ってこないけれど、自分が「これがいい／これは違う」と言葉で評価し続けると、出力の精度がどんどん上がっていく。

第四章：ビルドエラーじゃない、別の落とし穴

サイト制作で、僕が最初に味わった挫折は、「ダウンロードしたファイルをダブルクリックしても、画面が真っ白になる」事件でした。

Claude が作ったサイトのプレビューは、開発環境の中ではちゃんと表示される。ところが、ZIP にして自分の PC にダウンロードして、index.html をダブルクリックすると、ピクリとも反応しない真っ白なページ。

原因を Claude に聞いたら、こう返ってきました。

ブラウザのセキュリティ仕様で、file:// で開いたページから別ファイル（.jsx など）を fetch することはブロックされます。http:// で配信すれば動きます。

なるほど。静的サイトといえど、ローカルで開けるとは限らないのだと、ここで初めて知りました。VS Code の Live Server や、コマンドラインで python -m http.server を叩く方法、もしくは GitHub Pages に上げてしまう方法。Claude は3つの選択肢を並べて、それぞれの手順を丁寧に教えてくれました。

僕は GitHub Pages を選びました。無料・HTTPS 自動・独自ドメイン対応。サイト公開に必要なすべてが揃っていて、コストはゼロ。GitHub にリポジトリを作って、Settings → Pages から「Deploy from branch」を選ぶだけ。3分後には otodesk4193.github.io でサイトが世界に公開されました。

このとき、ちょっと震えました。
自分が作ったものが、URL を打てば、世界中のだれもが見られる状態になっている。これは、ローカルでビルドして「動いた」と喜んでいるのとは、まったく違う質感の感動でした。

第五章：訪問数と DL 数を、お洒落にカウントしたい

公開してから、僕はある欲求に襲われました。
「誰が来てくれているか、何回ダウンロードされたか、知りたい」。

Google Analytics を仕込むのが王道です。でも、僕はそこまで分析がしたいわけじゃない。サイトの一部として、訪問数とダウンロード数が見えればいい。それも、お洒落に。

Claude に相談すると、無料のカウンター API（abacus.jasoncameron.dev）を使う方法を提案してくれました。フェッチで叩くだけで、グローバルなカウンターを共有できる。これを各プラグインの「ダウンロード」ボタンの隣と、サイト下部に組み込んでもらいました。

結果、各プラグインカードの隣には「DL 数」の数値チップが、サイト下部には「訪問総数」が、オドメーター風にカウントアップするビジュアルとして配置されました。橙色のパルスドットが脈打つ "● LIVE" 表示付きで。

「サイトが生きている」感じが、グッと出ました。

第六章：Ambience を、最強の形で世に出すために

そして、僕が一年がかりで開発してきた中でも、最大の野心作 ── アルゴリズミック・リバーブ「Ambience」のリリースが近づいていました。

これは、僕が「商用リバーブへの不満」をぶつけきった、執念の塊のような作品です。
16 チャンネルの Feedback Delay Network、FWHT 帰還行列、Välimäki-Liski の 10 バンド GEQ 吸収、ISM ベースの Early Reflections、Anti-Derivative Anti-Aliasing 適用の 4 種サチュレーター、そして Abbey Road、Vienna Musikverein、Concertgebouw、Carnegie Hall を含む 21 種のファクトリープリセット。これを全部、無料で配ります。

こんなものを、他のプラグインと同じカードで横並びに紹介してたまるか。

そこで Claude に依頼しました。

Ambience を、サイトのプラグイン紹介の一番上に固定したい。
そこからキャッチを踏むと、Ambience だけの特設ページに飛ぶようにしたい。
特設ページは、リサーチグレード DSP の中身をセンセーショナルに紹介してほしい。

こうして生まれたのが、「空間を、支配する。」のキャッチで始まる Ambience 特設ページです。

otodesk4193.github.io/ambience.html
Ambience — Algorithmic Reverb

世界の名ホールを、16ch FDN に閉じ込めた。無料で。 — 21 のファクトリープリセット、7 つのアルゴリズム、リサーチグレードの DSP を、無料・オープンソースで。

このページは、ダーク基調で、暖色のグロウが効いた、いわば「映画のティーザーサイト」のような雰囲気でまとまりました。
"有料リバーブの 9 割は、実は同じものを隠して売っている。" と言い切るところから始まり、「FDN コア」「7 アルゴリズム」「Välimäki-Liski の絶対精度」「ISM Early Reflections」「ADAA サチュレーション」と、技術カードが続く。プリセット 21 種は、参照空間（Abbey Road Studio 2、Capitol Studio A、Tokyo Opera City…）を全部明記して列挙。最後は "Can you tell it apart from the paid ones?"（有料のものと、違いが分かりますか？）という挑発的な CTA で締めくくります。

正直、ここまで攻めた書き方ができたのは、自分のプラグインに、それだけの自信があるからに他なりません。実装の段階で、世界の名ホールの実測値を何百回と読み込んで、RT60 と D50 と C80 を一つひとつ追い込んで、その上で「これは商用品と並べても引けを取らない」という確信を持って、世に出しているからこそ、こういう挑発が成立する。

第七章：Before / After 動画も、自前で作った

Ambience のリリースに合わせて、YouTube で Before / After のデモ動画も公開しました。

普通なら、動画編集ソフトでタイトル画面を作るところ。でも、僕にはそんなスキルもソフトもありません。Claude に相談すると、「HTML で 1920×1080 の Before / After 画面を作って、ブラウザでフルスクリーン表示しながら画面録画すればいい」と提案してくれました。

確かに、それなら自分にもできる。
キーボードの ← → で切り替えできる Before / After タイトル画面を作ってもらい、OBS で画面録画して、音声と合成しました。Before 画面は乾いた波形と「DRY.」、After 画面は橙のグロウと豊かなテール波形と「WET.」。そのまま動画の冒頭と後半のタイトル素材として使えました。

第八章：完成。そして、ここからの話

こうして、OTODESK の公式サイトは、Ambience の正式リリースと同時に、完成しました。

プラグインは 12 個。
公式サイト 1 枚と、Ambience 特設ページ 1 枚。
日英バイリンガル対応。アクセントカラー切替の Tweaks 機能つき。訪問カウンターと DL カウンターつき。
GitHub Pages で完全無料ホスティング。

振り返ってみると、これだけのものを、僕は一行も自分で HTML を書くことなく、AI との対話だけで完成させたことになります。プログラマでも、デザイナーでも、ライターでも、動画クリエイターでもない一介のサラリーマンが、です。

これからは、サイトをハブにして、もっとプラグインを使ってもらう活動をしていきたいと思っています。バグ報告も、機能リクエストも、感想も、全部歓迎です。誰かが反応してくれると、僕は犬のように「ワンっ」と吠えて喜びます。

素人がこれから AI でサイトを作る人へ、最後の伝言

長くなりましたが、最後にいくつか伝言を。

1. AI に「すべてお任せ」しない。
最初の質問にちゃんと答える。配色、ターゲット、トーン、含めたい要素。これを決めずに「いい感じで作って」と言うと、いい感じでなく、よくあるものが返ってくる。

2. 「これは違う」と言葉にする。
出力を見て、何が違うと感じたのか、自分の言葉にする。「もっと暖かい色」「下線は不要」「ここを強調」と、具体的に。具体的なフィードバックの量だけ、AI の出力精度は上がる。

3. ローカルで動かないことを恐れない。
file:// でダブルクリックして真っ白でも、それは仕様。GitHub Pages に上げれば普通に動く。怖がらず、上げてしまえばいい。

4. 「素人だから」を言い訳にしない。
専門教育を受けていない自分にできることは、限られています。でも、執念だけは限らない。なんども躓いて、なんども書き直して、それでも一個ずつ理解していけば、必ず形になる。AI は、その執念を持つ人にとって、史上最高の相棒です。

音楽もそうですよね。
コードを知らなくても、音楽理論を学んでいなくても、頭の中で鳴っている音をなんとか形にしたい執念さえあれば、トラックは完成する。プラグインも、サイトも、それと同じです。

では、また。
